Benutzerhandbuch — Shell Sentinel

Überblick

Shell Sentinel ist eine Terminal-Anwendung, die eine persistente SSH/SFTP-Sitzung zu einem entfernten Server aufbaut und einen KI-Assistenten bereitstellt, der natürliche Sprache in überprüfbare Administrationsaufgaben umsetzt.

Voraussetzungen

  • Terminal mit Farbfähigkeit (empfohlen xterm-256color).
  • Python 3.12 (siehe .python-version).
  • Zugriff auf einen Server mit aktivem SSH/SFTP.

Installation

  1. Virtuelle Umgebung erstellen:
python3.12 -m venv .venv
source .venv/bin/activate
  1. Abhängigkeiten installieren:
make install

Sprachkonfiguration

Die Anwendung liest SMART_AI_SYS_ADMIN_LOCALE. Ist die Variable nicht gesetzt, wird das Systemlocale verwendet (Standard: Englisch). 

export SMART_AI_SYS_ADMIN_LOCALE=de   # Deutsch
export SMART_AI_SYS_ADMIN_LOCALE=en   # Englisch
export SMART_AI_SYS_ADMIN_LOCALE=es   # Spanisch

Start der Anwendung

make run

Beim Start erscheint ein retro-inspirierter Begrüßungsbildschirm, der sich nach fünf Sekunden schließt oder sobald eine Taste gedrückt wird.

Oberfläche

  • Gesprächspanel: zeigt Antworten des Assistenten im Markdown-Format.
  • Eingabefeld: mehrzeilig; Standard-Tastenkombination zum Senden ist Ctrl+S.
  • Fußzeile: informiert über den SSH-Status sowie Provider-/Modellinformationen.

Wichtige Befehle

Alle Befehle stehen auf Englisch, Spanisch und Deutsch zur Verfügung.

  • /connect <host> <user> <password|key_path> [Port] — baut die SSH-Sitzung auf (Standardport 22). SFTP wird bei der ersten Übertragung geöffnet.
  • /disconnect — beendet die aktive Verbindung.
  • /help — listet verfügbare Befehle.
  • /status — zeigt Agenten-, Provider- und Modellstatus.
  • /exit — öffnet den Bestätigungsdialog zum Beenden.

Arbeiten mit dem Assistenten

Formuliere Anweisungen in natürlicher Sprache. Wenn es kein Slash-Befehl ist, verarbeitet der Strands-Agent die Eingabe. Beispiele:

  • Zeige die Prozesse mit der höchsten CPU-Auslastung
  • Lade /tmp/script.sh nach /home/ubuntu/bin/script.sh hoch

Der Assistent nutzt die aktive SSH-Sitzung für Befehle. Dateiübertragungen öffnen SFTP bei Bedarf und protokollieren jede Aktion ausführlich.

Konfiguration

  • conf/app_config.json enthält Styles, Texte und Shortcuts als Platzhalter wie {{ui.output_panel.title}}, die pro Locale aufgelöst werden.
  • Übersetzungen befinden sich unter conf/locales/<sprache>/strings.json. Neue Texte werden im Code mit _("schlüssel") referenziert und für jede Sprache gepflegt.
  • conf/agent.conf legt Provider, Tools und Timeouts fest. Nutze conf/agent.conf.example als Ausgangsbasis. OpenAI unterstützt chat_completions (Standard) und responses; gemeinsame max_tokens- und Reasoning-Werte werden für den gewählten Endpoint normalisiert. Nutze Responses für GPT-5.x Function Tools mit aktivem Reasoning. Optionales stateful kann previous_response_id wiederverwenden, aber reasoningContent behält noch keine vollständige Multi-Turn-Kontinuität.
    OPENAI_API_KEY bleibt in der Umgebung. Das Beispiel nutzt gpt-5.6-sol, Responses, reasoning_effort: medium und max_tokens: 32768 (effektiv max_output_tokens); die reale Konfiguration nutzt 65536. Bedrock bleibt bei 8192, der Remote- Timeout bei 900 Sekunden und remote_command.max_output_chars: 120000.
    Für LM Studio lms server start ausführen; für Cerebras CEREBRAS_API_KEY exportieren. Mistral AI nutzt MISTRAL_API_KEY, provider: mistral, standardmäßig reasoning_effort: high und max_tokens: 16184 (mistral-medium-3.5).

Fehlerbehebung

  • Farb-/Darstellungsprobleme: TERM prüfen und ggf. auf xterm-256color wechseln.
  • Assistent reagiert nicht: conf/agent.conf, Zugangsdaten und logs/app.log kontrollieren.
  • "Keine aktive SSH-Verbindung": Vor Remote-Aktionen /connect ausführen.
  • SFTP-Fehler nach erfolgreichem /connect: Die Remote-Shell kann Banner in nicht-interaktiven Sitzungen ausgeben (z. B. pyfiglet in ~/.bashrc). Dekorative Ausgabe nur interaktiv erlauben oder Subsystem sftp internal-sftp auf dem Server setzen.
  • Zugangsdaten in Logs: /connect-Passwörter werden in logs/app.log als *** maskiert.
